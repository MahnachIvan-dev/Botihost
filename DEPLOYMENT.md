# BotHost v9.9 Resource Guard — Railway (один сервис)

## Архитектура

В этом варианте **BotHost и кассир работают в одном Railway-сервисе**. Railway собирает `Dockerfile`, запускает `python -u bot.py`, а `bot.py` запускает `cashier.py` внутри того же процесса, если `CASHIER_TOKEN` задан и `INTERNAL_CASHIER=on` (или `auto`). Не создавайте второй сервис кассира и не запускайте тот же токен в другом месте. Установите `Replicas = 1`.

## Railway → Variables

Добавьте значения в панели Railway, не создавая и не загружая `.env`:

**Обязательные для BotHost и встроенного кассира:**

- `BOT_TOKEN` — токен главного BotHost от @BotFather.
- `CASHIER_TOKEN` — токен отдельного бота-кассира от @BotFather.
- `OWNER_ID` — числовой Telegram ID владельца.
- `OWNER_USERNAME` — username владельца без `@` (необязательно).
- `SYNC_CHANNEL_ID` — ID приватного канала синхронизации, например `-100...`; это не канал хранения архивов.
- `SYNC_SECRET` — длинный случайный секрет; держите его в секрете.
- `GROQ_API_KEY` — ключ Groq, нужен кассиру для проверки изображений.
- `VERIFIER_BOT` — username кассира без `@`, по умолчанию `BotHostoplatiBot`.
- `INTERNAL_CASHIER=on` — включить кассира внутри сервиса.

**Рекомендуемые ограничения ресурсов:**

- `DATA_DIR=/app/data`
- `MAX_UPLOAD_MB=20`
- `MAX_PROJECT_MB=100`
- `MAX_ZIP_UNCOMPRESSED_MB=100`
- `MAX_ZIP_FILES=500`
- `MAX_ZIP_RATIO=200`
- `MAX_ZIP_DEPTH=12`
- `MAX_TOTAL_BOTS_MB=2048`
- `MIN_FREE_DISK_MB=256`
- `MAX_BOT_LOG_MB=8`
- `BOT_MONITOR_INTERVAL=5`
- `ARCHIVE_COOLDOWN_SECONDS=2`
- `MAX_PARALLEL_STARTS=1`
- `RATE_LIMIT_EVENTS=25`
- `RATE_LIMIT_WINDOW=10`
- `CASHIER_MAX_CONCURRENT_CHECKS=1`
- `CASHIER_IMAGE_SIDE=1600`
- `CASHIER_IMAGE_MAX_BYTES=3500000`
- `CASHIER_RAW_IMAGE_MAX_BYTES=10000000`
- `CASHIER_RATE_EVENTS=20`
- `CASHIER_RATE_WINDOW=10`
- `CASHIER_COOLDOWN_MIN=5`
- `CASHIER_SERVICES=0`
- `GROQ_VISION_MODEL=qwen/qwen3.8-27b` (проверьте доступность модели для вашего ключа)

Не нужно вручную задавать остальные настройки, если не хотите переопределить значения по умолчанию. `BOTHOST_USER_ENV` оставьте `{}`. `BOTHOST_BOT_TOKEN` оставьте пустой, если вам не нужен специальный сценарий передачи токена пользовательским ботам.

## Хранилище

Подключите Railway Volume к пути `/app/data`. В нём находятся SQLite-база, файлы пользовательских проектов и состояние кассира. Без постоянного Volume данные могут потеряться при пересоздании контейнера. Размер Volume должен учитывать лимиты `MAX_TOTAL_BOTS_MB` и запас свободного места.

## Каналы Telegram

Добавьте оба бота в приватный канал синхронизации и выдайте необходимые права. `SYNC_CHANNEL_ID` и `SYNC_SECRET` используются обоими компонентами. `BOT_FILES_STORAGE_CHANNEL_ID` — другой, необязательный канал для хранения файлов; если его не используете, оставьте `0` или не задавайте. `STORAGE_CHANNEL_ID` — альтернативное имя этой же переменной хранения, а не синхронизации.

## Сборка и запуск

- Railway использует `railway.json` и корневой `Dockerfile`.
- Dockerfile устанавливает зависимости из `requirements.txt`, копирует оба Python-файла и выполняет `py_compile` во время сборки, чтобы синтаксические ошибки обнаруживались до запуска.
- Установите в Railway одну реплику. Не запускайте `cashier.py` отдельно при `INTERNAL_CASHIER=on`.
- Если сборка всё ещё падает, откройте полный Build Logs: сводка `Deployment failed during the build process` не содержит самой ошибки.

## Ограничения

Лимиты снижают риск перегрузки, но не гарантируют отсутствие OOM: пользовательские процессы могут суммарно потреблять больше RAM, чем выделено сервису. Не запускайте недоверенные пользовательские боты без изоляции и контроля ресурсов.


## Интеграция с ботом заказов (скриншоты через кассира)

Для заявок формата `/payment_request UID PLAN ORDER_NUMBER` с дополнительной строкой
`ORDER_ID=...` кассир теперь показывает пользователю кнопку оплаты и запускает
обычный сценарий проверки двух скриншотов. Идентификатор `PLAN` должен быть описан
в переменной Railway `CASHIER_ORDER_PLANS_JSON`. Пример (замени `PLAN1` на точный
код тарифа, который администратор вводит в боте заказов):

```json
{"PLAN1":{"name":"Оплата заказа","stars":15,"days":1,"kind":"bot","emoji":"💳"}}
```

`stars` — стоимость, которую кассир использует при проверке скриншота. Установи
одинаковый `SYNC_CHANNEL_ID` и `SYNC_SECRET` у кассира и бота заказов. В боте
заказов оставь `VERIFY_PAYMENT_SIGNATURE=1`. Для этой интеграции кассир отправляет
результат с HMAC в формате, который проверяет существующий бот заказов; его код
менять не требуется. Не добавляй `ORDER_ID`-заявки в публичный канал: используй
только закрытый канал синхронизации, куда писать могут только доверенные боты/
администраторы.
