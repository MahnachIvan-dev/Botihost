# BotHost v9.9 — Защищённая сборка с ограничением нагрузки

Telegram-хостинг Python-ботов + AI Cashier с дополнительной проверкой оплаты владельцем.

Версия 9.9 включает защиту от небезопасных ZIP, общие квоты хранилища, ограничение логов и восстановление состояния заморозок оплаты после перезапуска.

### Что изменено

- исправлены гонки `start/stop/restart`;
- исправлен `KeyError` в `running_bots`;
- SQLite WAL + busy timeout + retry;
- автоматическая выдача слотов через подписанный канал;
- `APPROVED/REJECTED` события от кассира;
- защита от повторной выдачи по `grant_id`;
- пользовательские переменные без `.env` файлов;
- отдельное `.venv` на каждый пользовательский проект;
- автоустановка `requirements*.txt`;
- автоустановка распространённых отсутствующих Python-пакетов;
- авто-рестарт пользовательских ботов;
- AI-дебаггер логов;
- безопасная распаковка ZIP: защита от ZIP-бомб, traversal, ссылок и частичной записи;
- лимит отдельного файла 20 МБ, проекта 100 МБ и общего хранилища;
- лимит свободного места, сериализация архивации и ограничение параллельных запусков;
- ограничение логов и пауза авто-рестарта после повторных падений;
- дополнительная проверка оплаты владельцем после одобрения кассиром;
- автоматическая временная заморозка пользовательских ботов при подтверждённой неоплате;
- ограничение размера скриншотов и числа параллельных AI-проверок;
- Cashier с двумя изображениями для проверки;
- допуск времени проверки — до 10 минут;
- модель Cashier по умолчанию: `qwen/qwen3.8-27b`;
- более компактное и понятное меню BotHost.

Подробный деплой: `DEPLOYMENT.md`.


Для Railway с BotHost и кассиром в одном сервисе используйте корневой `Dockerfile` и `railway.json`. Настройки переменных окружения и Volume описаны в `DEPLOYMENT.md`.


## Интеграция с ботом заказов (скриншоты через кассира)

Для заявок формата `/payment_request UID PLAN ORDER_NUMBER` с дополнительной строкой
`ORDER_ID=...` кассир теперь показывает пользователю кнопку оплаты и запускает
обычный сценарий проверки двух скриншотов. Идентификатор `PLAN` должен быть описан
в переменной Railway `CASHIER_ORDER_PLANS_JSON`. Пример (замени `PLAN1` на точный
код тарифа, который администратор вводит в боте заказов):

```json
{"PLAN1":{"name":"Оплата заказа","stars":15,"days":1,"kind":"bot","emoji":"💳"}}
```

`stars` — стоимость, которую кассир использует при проверке скриншота. Установи
одинаковый `SYNC_CHANNEL_ID` и `SYNC_SECRET` у кассира и бота заказов. В боте
заказов оставь `VERIFY_PAYMENT_SIGNATURE=1`. Для этой интеграции кассир отправляет
результат с HMAC в формате, который проверяет существующий бот заказов; его код
менять не требуется. Не добавляй `ORDER_ID`-заявки в публичный канал: используй
только закрытый канал синхронизации, куда писать могут только доверенные боты/
администраторы.
